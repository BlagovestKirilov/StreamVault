## Architecture

StreamVault is a Stremio addon (Express.js HTTP server) that proxies IPTV streams from Xtream Codes API servers or M3U playlists into the Stremio protocol. **Live TV only** — VOD/series are intentionally dropped (memory).

### Core files

All server code is in **`src/`** (one flat folder; `npm start`, the Dockerfile `CMD` and `package.json` `main` point at `src/addon.js`). `public/` and the local `stats.json`/`links.json` folder are resolved from `ROOT` (`util.js`; = the project root, one level above `src/`) — never `__dirname` directly. Tests require `../src/<module>`; child-process tests run with `cwd` = `src/`.

- **`src/addon.js`** — Express routes, config parsing, caching, encryption, analytics, and all Stremio protocol handlers.
- **`src/configlink.js`** — install link settings: AES-256-GCM `encryptConfig`/`decryptConfig` (key from `CONFIG_SECRET`; refuses to start in production without it), the link formats (`configFromSettings`, `settingsFromEncrypted`, `settingsFromBase64`, `configFromQueryString`), `isPlaylistLink`, `normalizeXtreamLogin`. Pure functions; `parseConfigPath` (needs the link store) stays in addon.js.
- **`src/catalog.js`** — channel lists, pure (no I/O): search matching (`normalizeForSearch`, Cyrillic→Latin), channel order (`sortChannels`, `nameKey`, quality tags), one tile per channel (`catalogView`, `channelTitle`), display names (`cleanName`), posters (`makePosterUrl`, `channelPoster`, `catalogMeta`).
- **`src/util.js`** — small shared helpers: `ROOT` (project root), `safeError` (error text without URLs/credentials), `userAgent(req)`, `maskPath` (install links hidden in logged paths), `parseExtra` (Stremio extra params, tolerant of bad %-encoding), `withinMs` (value or fallback after a timeout).
- **`src/stats.js`** — usage statistics: `stats` (all-time counters, unique users as one-way codes `userKey`, per-day `history` rows via `countToday`/`countCode`, `recordError`), the in-memory `recent*` lists (`noteRecent`), `STATS_DIR`, saving (`saveStats` every minute, atomic temp+rename; `saveStatsSync` on shutdown). **`stats` is one shared object** — loading stats.json replaces its contents, never the object (other modules hold it). Shutdown handlers stay in addon.js (they also save the link store).
- **`src/xtream.js`** — Thin wrapper around the Xtream Codes HTTP API (categories, streams, short EPG, account info). Every call is SSRF-checked.
- **`src/m3u.js`** — Streaming M3U parser (`createLineParser`): live-only filter, unique ids, playlist headers, optional group filter, group-count mode.
- **`src/urlguard.js`** — SSRF protection (`validateExternalUrl`, `assertExternalUrl`, `blockPrivateRedirects`), plus `guardedAgents` (axios http/https agents whose DNS lookup refuses private addresses at connect time — covers DNS rebinding, redirects to internal hosts and the 5-min `okHosts` cache; every provider request must use them) keep-alive (idle connections closed after 4 s or the server's hint, max 16 per provider; `retryOnClosedConnection` resends a GET once on ECONNRESET/EPIPE — a reused connection the provider already closed), and `PROVIDER_USER_AGENT` (VLC) sent on every provider request — axios's default UA gets 403 from many panels).
- **`src/ratelimit.js`** — `getIp` (uses Fly's `Fly-Client-IP`; `X-Forwarded-For` is client-forgeable — verified) and `rateLimit(name, max, windowMs)`. Per IP per minute: provider checks (`/api/test`, `/api/categories`, `/api/m3u-groups`) 10, `/api/encrypt` + `/api/config` 30, `/stats` 5, addon routes 1500. Loopback is never limited (tests/local dev). Daily `history` rows also count `providerErrors` as `{ "<where> (<source>)": { "<status or kind>": n } }` (e.g. `"catalog (m3u)": {"503": 2}`) and `responseErrors` (our ≥400 responses incl. 429) as `{ "<METHOD route pattern>": { "<status>": n } }` — route patterns, never raw URLs (install links contain credentials).
- **`src/links.js`** — stable install links `s-<12 chars>`: id → encrypted settings (same AES as `e-` links) in `<STATS_DIR>/links.json` (+ `.bak` = previous version; an unreadable file is moved to `.corrupt-<ts>` and the backup loaded — never overwritten by an empty store). Atomic serialized writes, sync flush on SIGTERM. Cap 50k (then `/api/link` falls back to `e-`). Older links (`e-`/base64/plain) are edited in place too: new settings saved as an override keyed by SHA-256 of the link (link not stored); `parseConfigPath` applies it. **Losing links.json breaks every `s-` install** (back it up with the volume); edited old links just fall back to the settings inside them.
- **`public/configure.html`** — Configuration UI; category/group picker; the Install / Saved result is a native `<dialog id="result">` opened with `showModal()` (Sonar S6819: no `role="dialog"` divs) — browser top layer, `::backdrop`, focus and Esc; centred on phones and PCs; × / Esc / tap on the backdrop close it (`openResult`/`closeResult`; a click whose target is the dialog itself is the backdrop, content sits in `.result-body`); page scroll locked while open and restored by `resultClosed` (called directly and on `cancel`/`close`, idempotent — don't rely on the close event alone); no motion with reduced-motion; Copy and **Open in app** always show (no per-app logic); Install calls `/api/link` (stable link). Works for Stremio and Nuvio (button says "Install", not "Install to Stremio"; result box says where to paste the link in either app; player tip: Stremio needs VLC, Nuvio uses its internal player and must be restarted after installing; each app's tip also says where its channels are — Stremio (Stremio-style icon): Board → "StreamVault Live" row or Discover → TV channels; Nuvio: Home → "StreamVault Live" row). A playlist link (`.m3u/.m3u8`, also a bare `http://name.m3u`) typed into the Xtream server field moves to the M3U tab; `/api/test` says "use the M3U tab" for it too. In edit mode the button reads **"Save changes"** (after the saved setup loaded) and a save that updates in place still opens Stremio (`stremio://` same link): Stremio keeps its stored manifest until the addon is installed again — verified, it does NOT refresh on its own even when the version changes — so on a PC opening the same link shows its dialog with **Upgrade** (same transportUrl = replaced, no duplicate). Not on phones (`ON_PHONE`, user agent): the Stremio phone app's dialog for an installed addon has **no** Upgrade — there the hint says Open in app → Uninstall → Install in the same dialog, then restart Stremio (same link, settings stay). "Open in app" opens the `stremio://` link (`stremioAppLink`: `https://` → `stremio://`), never Stremio Web; Nuvio registers `stremio://` too, so Android asks which app to open — that's why the label names no app. Opened from an installed addon's Configure (`/<link>/configure`) it sends `editing: <link>`: the link is updated in place ("Saved — StreamVault updated", nothing to reinstall) — `s-` links directly, older links via an override. Only a full store or an unreadable old link gives a new link. **No app detection** (removed on purpose: User-Agents are unreliable — Nuvio Android sends `okhttp/5.x`, Stremio Android none — and a wrong guess shows the wrong instructions). Both tips always show; `savedHint()` (device only, `ON_PHONE`): Stremio on a PC "Stremio opens StreamVault — press Upgrade there", on a phone Open in app → Uninstall → Install → reopen Stremio; then on its own line "In Nuvio: fully close and reopen the app." (`#restartHint` is `white-space: pre-line`). Old `linkApps`/`userApps`/`installsByApp` keys are deleted from stats.json on load.
- **`src/metrics.js`** — Prometheus text writer, per-route request count + duration histogram (fed by the first `finish` middleware), event-loop delay. `buildMetricsText()` in `addon.js` exports memory/CPU/event loop, caches, downloads, stable links, all-time counters and **today's** `history` row (`streamvault_today{counter=…}`, `streamvault_today_provider_errors`, `streamvault_today_response_errors`) plus the seven recent lists as `streamvault_recent_*` (one series per entry, labels = entry fields in snake_case, value = event unix time; shown as tables). Served by a second HTTP server on `METRICS_PORT` (9091, only when run directly — not in tests); `fly.toml` `[metrics]` points Fly's scraper at it and it is **not** a public service. Fly's Grafana: **fly-metrics.net** → import `grafana/streamvault-dashboard.json` (choose "Prometheus on Fly"). A new stats counter shows up automatically under `streamvault_today`; add a panel if it matters. The dashboard also has a "Fly machine and network" row built on Fly's own series (`fly_instance_cpu` incl. steal, `fly_instance_memory_*`, `fly_volume_used_pct`, `fly_edge_*`, `fly_app_concurrency`, filtered `app="streamvault"` — check names in Explore if a panel is empty) and a "Restarts / deploys" annotation (`resets(streamvault_uptime_seconds[2m]) > 0`). Dashboard JSON is generated; keep uid `streamvault` so re-import overwrites. Top row starts with All-time installs, then Viewers today. Request panels: a fixed colour for **every** route (`ROUTES` in the generator: catalog green, search/page light green, manifest purple, meta yellow, stream orange, /play blue, configure teal, api pink/amber/magenta, empty installs brown, probes slate, health mint, 404s grey; never red). Grafana's `byRegexp` matches the **whole** series name — patterns must end in `$` or `.*`. Colours: red only for real failures (5xx, CPU steal), orange for 4xx, fixed per-series colours or shades of blue elsewhere — Grafana's default palette paints the 5th series red, which reads as an error.
- **`tests/addon.test.js`** — Jest + Supertest tests. Upstream calls are mocked with `jest.spyOn(m3u|xtream, ...)`.

### Request flow

1. User opens `/configure`, fills in Xtream or M3U details, presses **Test Connection** (it also returns the category/group list — there is no separate "Load Categories" button), optionally picks categories/groups, presses **Install**.
2. The UI calls `POST /api/link`: settings are AES-256-GCM encrypted and saved under a stable `s-<id>` link (`links.js`); the page opens `stremio://…/manifest.json` (Stremio or Nuvio offers to install). `POST /api/encrypt` (self-contained `e-` link) still exists for older clients/tests.
3. The app installs `/:config/manifest.json`. The configured manifest lists the user's groups as catalog `genre` options (`getGenresWithin`, cached 6h, 8s timeout → no dropdown).
4. Stremio calls `/:config/catalog|meta|stream/:type/:id.json`.
5. Each handler decrypts `:config`, fetches from Xtream / the M3U URL (cached), returns Stremio JSON.

Other endpoints: `POST /api/test` (connection test + Xtream account info), `POST /api/categories` (Xtream), `POST /api/m3u-groups` (M3U group names + counts, no channels kept), `/play/...` (redirect so VLC shows the channel name), `/stats?key=` (all-time usage, `history` = 90 days of per-day counts incl. failures, `recentErrors` since restart, `memory`/`caches` telemetry), `/health`.

### Config encoding

Four formats for the `:config` segment (`parseConfigPath`): **stable** `s-<id>` (current — looked up in `links.js`, unknown id → 400 "no longer exists"; cache keys that depend on settings use `req.configKey` = `<id>@<revision>`), **encrypted** `e-<hex>` (current, keyed by `CONFIG_SECRET`), **base64url** JSON (legacy), **URL-encoded** (oldest). Short keys: `t` type, `s`/`u`/`p` Xtream server/user/pass, `m` M3U URL, `c` Xtream category ids (comma-joined), `g` M3U groups (JSON array string), `z` viewer timezone (IANA). Allowed keys are whitelisted in `ALLOWED_CONFIG_KEYS`; values are capped at 2048 chars (`g` over the cap is rejected, not truncated).

### Stremio details worth knowing

- Catalog extras are parsed from the **raw** path (`req.path`), not `req.params` (already decoded — breaks `&` in names).
- Search (`normalizeForSearch`) ignores case, accents, punctuation and Cyrillic vs Latin (`бнт` = `BNT`); every word must appear in the name.
- Stats never store IPs: unique users (`users`, `dailyActive`, `dailyViewers`) are `userKey(ip)` = 16-hex HMAC keyed from `CONFIG_SECRET` (changing the secret resets the count; old plain-IP entries are converted on load).
- `dau` = unique users whose app loaded StreamVault that day (every app start); `viewers` = unique users who opened a channel and got ≥1 stream back (stream handler, `addDailyUser`). Both kept as per-day Sets for 30 days in stats.json and frozen into the 90-day `history` rows (`uniqueCounts`); `/stats` shows `dailyActiveUsers` + `dailyViewers` (7 days), `/metrics` `streamvault_today{counter="dau"|"viewers"}`. M3U playback goes straight to the provider, so a viewer is "wanted to watch", not confirmed playback.
- M3U ids: first entry keeps the bare `tvg-id`; duplicates get `_v2`, `_v3`. Ids are assigned before the group filter so they are stable across selections. Streams return the picked channel + up to 5 same-`tvg-id` variants.
- Channel order (`sortChannels`, all installs, no setting): picked categories in **pick order** (Xtream `c` ids / M3U `g` names = click order, shown as chips on the configure page; edit mode keeps it, newly ticked go last), otherwise categories A–Z; channels A–Z inside by `normalizeForSearch(name)` (case, accents, punctuation, leading/odd spaces ignored, Cyrillic transliterated **by sound** — so hidden characters and same-sound look-alikes А/О/Е/Т/К/М don't move a channel, but Cyrillic В/Н/Р/С/Х/У sort as v/n/r/s/h/u; Cyrillic names sort by their Latin spelling: БНТ ≈ bnt), ignoring quality tags (`QUALITY_TAGS`: SD/HD/FHD/UHD/4K/720p/1080p/HEVC/50FPS…, also in `()`/`[]`) so "BTV", "BTV HD", "BTV UHD" stay together before "BTV ACTION" (same base → lower quality first); a trailing "TV" word is ignored too ("NOVA TV" sorts with "NOVA", before "NOVA SPORT"; "BTV"/"TVN"/"TV 1000" unaffected); no category / M3U's "Uncategorized" last. Sort keys are computed once per channel (10k ≈ 50 ms). `Intl.Collator("en", {sensitivity:"base", numeric:true})` — any script (Latin, then Greek, then Cyrillic), case/accents ignored, "Sport 2" before "Sport 10". Sorted once per cache load (Xtream catalog cache; M3U via a WeakMap keyed by the cached playlist), never per request; the genre dropdown follows. Names are never changed (no numbers added).
- Xtream expiry notice: on the first catalog page (not search, not `skip>0`) the account is read alongside the channels (gives up after 3 s, `ACCOUNT_WAIT_MS`). ≤7 days left → first tile `iptv_notice_expiring` "⚠️ Subscription ends in N days" ("in less than a day" under 24 h); expired/disabled while the panel still lists channels → the `iptv_notice_account` tile first. Opening the expiring tile after a renewal says "✅ Subscription renewed". A first page with a tile has 101 items, so a `skip` of 101, 201… (apps counting items received) is read as 100, 200….
- **Home rows** (`categoryRows`): with ≥2 picked categories the manifest adds one catalog per category (pick order, max 8, after `iptv_live`), id `iptv_cat_<12 hex of sha256(name)>` (stable across edits, `categoryForRow` maps it back; unknown id → empty row), extra `skip` only. The expiry tile is main-row only. Manifest version 1.2.0. Apps keep the manifest (genre options, rows) they loaded at start, so after the setup changes they can still offer a category that's no longer picked: such a genre/row answers one "⚠️ No channels in this category" tile (`staleCategoryAnswer`, `NOTICES.category_gone`: an older category list, or a picked category the provider emptied — reopen the app or check Configure) instead of an empty screen; counted per day as `staleCategories`. If the channel list isn't ready within `GENRES_TIMEOUT_MS` (e.g. right after Save changes added a category, big list), the manifest falls back to the **picked** category names (`pickedCategoryNames`: M3U `g` names; Xtream ids → names via `get_live_categories`, 3 s) so the app never caches a manifest without them.
- **Merged versions** (`catalogView`, WeakMap per cached list): channels in the same category whose names differ only by **trailing** quality tags (`QUALITY_TAGS`) and/or a trailing "TV" (`mergeWords`: "BOX TV" + "BOX UHD", "BALKANIKA MUSIC" + "BALKANIKA MUSIC TV UHD"; exact duplicate names too) are one tile — named like the plain (untagged) version (`titles`, `stripQualityTags`), id of the best version. Streams: every version best quality first, whichever version's id was opened (Xtream: TS+HLS each; M3U: same-name versions, then same tvg-id). Max 6 versions. Old saved ids of any version still resolve. "TV 1000"/"BTV"/"TVN" keep their "TV" (only a last word "TV" after other words is ignored).
- **Clean names** (always on, every install, no setting): `cleanName` strips up to two leading tags (`NAME_PREFIXES`: one simple regex per tag shape — one combined regex was over Sonar's complexity limit) — `[..]`/`(..)`/`|..|` (≤8 chars), `ABCD|`, 2-letter `UK:`/`BG -` — from tile, row, channel page, stream titles and the /play name. Display only: ids, sorting, search and the genre dropdown use the raw names.
- Channel page TV guide (Xtream only): just **Now + Next** (`guideLines`/`nowAndNext`), picked by the provider's `start_timestamp`/`stop_timestamp` (panels may start at the next show or include ended ones), titles only, times in the viewer's zone (`epgTimeRange`); no timestamps → the first two entries; nothing on now → Next only.
- Stream `name` = left column in Stremio ("StreamVault\nTS"), `title` = right side. Xtream titles: channel name, then the format ("MPEG-TS" / "HLS / m3u8"), no hints; same for every app. The configure page's Nuvio tip says that on Samsung (Tizen) TVs Nuvio is the only way to use StreamVault (Nuvio itself also runs on Android).
- Bump `BASE_MANIFEST.version` when the manifest shape changes so clients refresh it. Apps keep the installed manifest and replace it when its version changes, so a saved link's configured manifest reports `1.2.<revision>` (`manifestVersion(req.configRevision)`; each Save changes bumps the revision) — new/removed categories and rows reach the app. Never-saved links report the base version. The Saved box also says: still the old categories → remove StreamVault in the app and install it again with the same link.
- Manifest description: the empty install says "Not connected yet. Open Configure … Already have a connected StreamVault? Delete this one."; a configured one says "✓ Connected to your <Xtream account|M3U playlist>. If another StreamVault only shows “Set up StreamVault first”, delete that one." Apps keep the description from **install time**, so text that must reach old installs belongs in live responses (tiles), not the manifest.
- A saved `<tvg-id>_v2/_v3` id that no longer exists (the provider changed the number of copies) falls back to the base channel (`findM3UChannel`); `m3u_<name>_<pos>` ids fall back to the same name at the nearest position.
- Test Connection hints: "use http:// instead of https://" only when the entered address really starts with `https://`; an SSL error on an `http://` address gets a "secure-connection (SSL) problem" message.
- Logs: `[INSTALL]` is written only for NEW installs (returning users re-read the manifest constantly; they're counted as `launches`/`dau`). A failed background refresh logs one `[REFRESH]` line even when several requests shared it.
- Provider HTTP 451 (blocks servers by country/data centre) is treated like 401/403: "Provider refused access" tile, its own Test Connection hint.
- `/<link>/configure/manifest.json` (configure-page link pasted into an app, which appends /manifest.json) is answered as `/<link>/manifest.json`.
- `HEAD /` redirects to `/configure` like `GET` (uptime monitors check `/` with HEAD). Film/series/anime requests to an empty install count as `foreignRequests`, not `unconfigured`. `X-Powered-By` is disabled.

### Memory (the server has crashed from OOM before — keep it bounded)

- Fly VM 1 GB, `--max-old-space-size=640`. Heap watchdog every 10s (`checkMemory`): >450 MB evicts the oldest half of the M3U **and** Xtream caches, >550 MB clears all caches; after either it runs a full GC (`collectGarbage`: `--expose-gc` set at runtime via `v8.setFlagsFromString`, not a startup flag) and logs the heap after collection — without it `heapUsed` stayed high and it cleared every cache every 10 s for minutes.
- All caches are **least-recently-used**: `setCapped` re-inserts on store and `touch` re-inserts on every read hit (a Map keeps insertion order), so a full cache — and the watchdog's "oldest half" — drops the entry unused for longest, never a busy one that was added early. Read cache entries through `touch`, not `cache.get`.
- Caches: M3U playlists 10 min TTL, max **15** entries (≈2–5 MB parsed per 10k-channel list, ~1.5× with its sorted catalog + merged view; 15 peaked ~125 MB — raising to 40/50 on 2026-10-22 drove the heap to 591 MB with 43 clear-all evictions, don't raise without measuring) (key = URL + selected groups); Xtream catalogs 4h, max **25** (no channel cap — big panels return 30k+ channels) (raw logos only — poster links built per response); Xtream account info 30 min (a failed lookup / no info retried after 3 min, `ACCOUNT_RETRY_MS`), shares the 25 cap; genres 6h, max 500; TV guide (`epgCache`, per panel + stream id, not per user) 3 min, max 1000, failures not kept. A capped 10k-channel parse ≈ 5 MB heap.
- Stale-while-refresh (`usableEntry`): after its TTL an M3U list (+50 min), Xtream list (+4 h) or account info (+6 h) is still answered at once while **one** background load refreshes it (`once()`, download slots and the failure cache still apply); a failed refresh keeps the old copy (logged `[REFRESH]`, not counted as a provider error). Only older/missing entries make the request wait. `POST /api/link` (Install / **Save changes**) calls `forceRefresh`: drops that setup's cached list (exact key via `m3uCacheKey`/`xtreamCacheKey`), its failure-cache entry and the Xtream account, so the next request downloads fresh — at most once per 2 min per setup (`FORCED_REFRESH_MS`). The configure page says so under Save changes ("Saving also reloads your channel list from your provider"). The 10-min sweep deletes entries past TTL + stale window; the heap watchdog clears all (incl. EPG) as before.
- `withFailureCache()`: a provider that just failed is not retried for 2 min (requests fail fast with the same error/tile); `/stats` → `caches.failedProviders`. Repeats answered from this cache — and requests that waited for the same failed download (`once()`; same error object, tracked in a WeakSet) — are counted as `history.cachedFailures` only (not logged/counted as provider errors); a `[FAILCACHE]` log line summarizes them on the next real retry.
- `/stats` also lists (in memory, last 20, masked) `recentUnknownPaths` (our 404s, with User-Agent), `recentEmptyStreams` (with reason), `recentUnconfigured` (bare-manifest installs, with User-Agent) and `recentPlayRejects` (why `/play` refused). `history.foreignRequests` = items that aren't this install's channels, answered without touching the provider: non-`iptv_tv_` ids (IMDb, other addons' `iptv_…`) and, on Xtream installs, ids that can't be an Xtream stream id (an M3U install's `iptv_tv_name.cc`).
- All-time `reconfiguresTotal` / `reinstallsTotal` in `/stats` (`stats.reconfigures` / `stats.reinstalls`, seeded once from the daily rows; `/metrics` `streamvault_reconfigures_total` / `_reinstalls_total`, Grafana tiles). Daily `history.reconfigures` = configure page opened from an installed addon (`/<link>/configure`); `history.reinstalls` = Install pressed in that mode (each one was a duplicate StreamVault before stable links). `/stats` → `caches.links` = saved stable links.
- **Broken install links** (stable link missing, no Xtream login, no playlist URL, unreadable) opened by an **app** — manifest / catalog / meta / stream — are answered like a bare install (`brokenLinkAnswer` in `extractConfig`'s refuse): bare manifest, setup tile, setup meta, Play → setup page (`SETUP_PLAY_STREAM`); foreign meta ids get `Unknown`. Still listed in `/stats` `recentBadLinks`. `/api/config/:config` (configure page) and `/play` keep their 400 errors. (A Nuvio retried a broken link hourly against a 400.)
- Bare installs (no settings) get the "Set up StreamVault first" tile; its poster is `public/img/setup-qr.png`, a QR to `/setup` (short link → coarse, TV-scannable code) which counts `history.setupScans` and redirects to `/configure?from=tile` (page shows a TV/app banner). For phones (can't scan their own screen): the bare stream for `iptv_notice_setup` is an `externalUrl` to `/setup?via=play`, the meta has `links` → `/setup?via=link`, and the description starts with "On this phone: tap Play"; `?via=` counts `setupTaps` instead of `setupScans`. The setup meta also carries `background` = `public/img/setup-bg.png` (1920×1080, QR card at the far right — apps put title/text on the left, and phones crop to the middle (Nuvio ~x 585–1335), so the card starts at x 1412; without it they stretched the square tile behind the text). Both PNGs are rendered from SVG with `qrcode` + `@resvg/resvg-js` (not project deps); keep error correction H (logo in the middle), integer-px modules, and bump the `?v=` on `SETUP_QR_URL`/`SETUP_BG_URL` when a picture changes (`/public` is cached 7 days).
- `[/<config>]/subtitles/...` (Nuvio asks every addon) → `{subtitles:[]}`, counted as `foreignRequests`. `/robots.txt` allows only `/configure` + `/public/` (install links stay out of search engines).
- `/<40-hex>/<n>/stats.json` (a client treating us as Stremio's streaming server, ~1/s) → 404, counted as `history.streamingServerProbes`, not in `recentUnknownPaths` / `responseErrors`. Same for `/<link>/manifest.<subtitle ext>` (a player given the install link probing for subtitles) → `history.subtitleProbes`.
- `/play` checks the provider address with `isExternalUrlSyntax` (scheme, length, no literal private host) — **no DNS lookup**, because only the viewer's player connects there; requests the server makes itself keep the full `validateExternalUrl` (DNS) + `guardedAgents`.
- Test Connection refuses an address that still contains a placeholder (`<FILENAME>` or `%3C…%3E`) with a "replace it" hint, without contacting anything.
- Never `substring()` user/provider text before `encodeURIComponent` — it can split an emoji and throw "URI malformed"; slice by code points + `toWellFormed()`.
- `withDownloadSlot()`: at most 4 big provider downloads (whole M3U playlists, full Xtream channel lists) run at once across all users; the rest queue. `/stats` → `caches.downloadsRunning` / `downloadsWaiting` (now) and per-day `history` → `downloads`, `downloadsQueued` (had to wait), `longestDownloadWaitMs`. Never call it from inside another slot (deadlock).
- `once(key, load)` dedupes concurrent cache misses so one playlist is downloaded once, not per request.
- M3U parse stops at 10k live channels; Xtream responses capped at 50 MB.
- Don't add per-user downloads of large files (e.g. XMLTV EPG) without strict size/concurrency limits.
- Check `/stats` → `memory` (peak, evictions) before changing cache sizes.

### Code rules (SonarQube — keep the scan clean)

The codebase was cleaned of all Sonar findings; new code must not bring them back:
- Built-in modules with the `node:` prefix (`require("node:fs")`, `node:path`, `node:crypto`, …).
- No regex that can backtrack on user/provider input (e.g. `/\/+$/` is quadratic on a run of slashes) — use a loop (`trimTrailingSlashes` in `urlguard.js`).
- Functions stay ≤ 15 cognitive complexity: route handlers dispatch to small helpers (see `parseConfigPath`, `/api/test` → `testXtream`/`testM3u`/`answerTestFailure`, `m3u.js` `addLine`, `configure.html` `install()`).
- No nested ternaries — a small function with early `return`s instead.
- No empty or comment-only `catch`: return/log something **and** say why the error is ignored. Don't reassign a function parameter in a catch; return the fallback.
- `x?.y` instead of `x && x.y` — but not where `""`/`0` must stay falsy differently (account status compares `status !== "" && status !== "active"`).
- `re.exec(str)` instead of `str.match(re)` for single matches; `replaceAll` for global literal replaces; `Number.parseInt(x, 10)`; sort strings with `localeCompare`; `toSorted()` when the sorted array is used in an expression (`.sort()` only as its own statement, for an in-place sort); `a >= b` instead of `!(a < b)` (check NaN explicitly).
- Promises: `async`/`await` instead of nested `.then` chains; a fire-and-forget call is written `void fn()` and only for functions that never reject (e.g. `links.js` `save()`).
- No SHA-1 (use SHA-256), no `X-Powered-By`.
- `configure.html`: every `<label>` has `for=`, inputs without a visible label get `aria-label`, no `!important`, no `user-scalable=no`.
- **No unused or dead code.** Delete what nothing uses — functions, constants, exports, CSS classes, configure-page functions — in the same change that stops using it (git keeps history). A parameter needed only for its position (Express `(req, res)`, `(err, req, res, next)`, mock callbacks) is prefixed `_` (`_req`). Export only what another module or the tests import. Check before committing: ESLint `no-unused-vars` (args: all, ignore `^_`) reports 0 on `*.js` and `tests/`, every `module.exports` name is imported somewhere, and every `configure.html` function/CSS class is referenced.
- Tests: in-process tests use a temp `STATS_DIR` (set at the top of `addon.test.js`); a `parseM3U` mock must honour its `groups` argument like the real parser; spawned Node processes run with `FORCE_COLOR=0` (IDE runners colour `console.log` output).

### Deployment

- Fly.io (`fly.toml`): 1 shared CPU, 1 GB RAM, AMS region, persistent `/data` volume (`vol_4qloqe1knpzep0nr`) for `stats.json` and `links.json`(+`.bak`). Daily volume snapshots kept **30 days** (`fly volumes snapshots list vol_4qloqe1knpzep0nr`); restoring = new volume from a snapshot, then attach it.
- If GitHub Actions is down: `fly deploy --remote-only` from the repo (deploys the local folder — commit first). GitHub's `FLY_API_TOKEN` is an app-scoped **deploy** token (`fly tokens list`).
- GitHub Actions (`.github/workflows/fly-deploy.yml`): lint + tests (Node 24) then deploys on every push to `master` — **pushing is deploying**, no manual `fly deploy` needed.
- **Never `git push` unless the owner explicitly says to push in that request.** Commit locally, report what changed, and wait. An earlier "push it" covers only that change.
- Docker: `node:24-alpine`, `npm ci --omit=dev`. `.dockerignore` keeps tests, `*.md`, `.github`, `.claude`, `grafana`, `.idea` and local data (`stats.json*`, `links.json*`) out of the image — the server must never read any of them.
